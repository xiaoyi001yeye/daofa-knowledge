# pdfs、daofa-build 与 daofa-qa 教材知识流程

**Status:** resolved

## Problem Statement

学习者需要依据教材回答初中《道德与法治》题目，但现有知识库只有 13 课占位稿，无法给出教材支持的答案。维护者已有扫描教材，缺少从扫描页面提取和核对文字、整理知识点并记录来源的可重复流程。现有答题技能也没有有效知识点和题眼索引可检索。

## Solution

提供三个相互交接的项目级技能及必要本地脚本：pdfs 处理和核对教材页面；daofa-build 整理知识点、Markdown、页码来源和题眼索引；daofa-qa 根据知识库分析题目并组织参考答案。

先用七年级上册第二课《正确认识自我》实现完整流程，验收后逐单元扩展至七年级上册全书。维护者能继续处理教材；学习者拉取知识库后能直接提问。

## User Stories

1. 作为维护者，我希望登记教材文件和指纹，以便区分同名但不同版本的来源。
2. 作为维护者，我希望检查 PDF 页面是否有可用文本，以便选择直接提取或 OCR。
3. 作为维护者，我希望扫描页面能使用本机简体中文 OCR，以便从已有教材开始处理。
4. 作为核对者，我希望获得清晰页面图、OCR 原始文字和坐标，以便修正错字、遗漏和阅读顺序。
5. 作为核对者，我希望教材页码与 PDF 页序分别保存，以便准确回到原教材页面。
6. 作为维护者，我希望 OCR 成功后保持未核对状态，以便学习者只使用已核对依据。
7. 作为用户，我希望 Codex 对照页面逐页核对，只将疑难部分交给我，以便减少人工工作。
8. 作为核对者，我希望保留原始识别结果及修订记录，以便追溯文字处理过程。
9. 作为维护者，我希望按页处理、失败后继续运行且保留核对修订，以便避免重复劳动。
10. 作为维护者，我希望来源变化时得到明确提示，以便避免将旧核对结果用于新教材。
11. 作为维护者，我希望将核对文本整理为逐课 Markdown 和独立知识点，以便继续沿用现有知识库。
12. 作为学习者，我希望每个知识点都有稳定编号和教材来源，以便理解与追溯答案依据。
13. 作为维护者，我希望跨页知识点保留所有相关来源，以便完整支持整理后的表达。
14. 作为学习者，我希望通过材料题眼和问法找到候选知识点，以便从材料理解考查内容。
15. 作为学习者，我希望答题前检查知识点正文，以便避免仅凭关键词选错知识。
16. 作为学习者，我希望答案按采分点组织并结合材料，以便直接用于初中考试作答。
17. 作为学习者，我希望考试模式精炼、讲题模式解释题眼映射，以便在不同学习场景使用同一依据。
18. 作为学习者，我希望未完成、未核对或不相关内容不会被当作教材观点，以便发现知识库的实际边界。
19. 作为学习者，我希望证据不足时明确提示“当前知识库依据不足”，以便不将猜测当作标准答案。
20. 作为知识库使用者，我希望没有本地教材 PDF 时仍可检索已经核对发布的知识，以便克隆仓库即可学习。
21. 作为维护者，我希望通过完整流程样例和可重复验证确认三者交接，以便放心扩展到其余课次。
22. 作为维护者，我希望环境缺少渲染或 OCR 能力时得到具体提示，以便保留已有进度并选择可用处理方式。

## Implementation Decisions

- 使用项目级技能交付，保留 daofa-qa 的既有用途和输出模式。重复的文件登记、渲染、OCR、校验及索引生成通过本地脚本实现；知识提炼、材料分析和自然语言作答由 Codex 完成。
- 第一版教材处理针对当前 Windows 环境，使用已有 Python 与 Poppler，并明确调用 Windows PowerShell 5.1 的 WinRT 简体中文 OCR。采用已有工具，不引入服务器或收费外部服务。
- 两种页码分别记录，封面等无印刷页码的页面使用空值。页面范围必须从教材核对，第二课已确认教材第 9–15 页对应 PDF 第 17–23 页；该偏移不自动推广到全书。
- 教材登记包含文件指纹。页面记录保留图像、提取方法、原始文本、OCR 坐标、核对文本、核对者和修订说明。继续处理前检查来源身份，保留已核对结果。
- 核对状态区分提取完成、核对通过和存在疑难。Codex 逐页对照图像核对；无法判断的内容保持待核对，由用户确认。OCR 后端没有置信度字段，不能构造虚假的置信度。
- 知识点按课组织在 Markdown 中，具有唯一稳定编号、章节、类型、整理表达、来源和适用题眼/问法。跨页知识点列出全部依据；题眼索引由有效知识点生成，避免手工维护两份内容。
- 教材原文、整理表达和答题提示有明确区分。知识点只有在来源已经核对且能支持其表达时进入 verified；draft 和占位内容不进入确定依据。
- 知识库继续只发布教材内容的结构化整理，不将扫描 PDF、页面图和完整 OCR 转录纳入共享内容。已发布知识点保存书目信息、指纹及双页码来源；原始材料在维护者本地保留。学习者缺少原始材料时仍可使用已核对知识，但不声称本次已重新核对原教材。
- daofa-qa 先识别题眼和设问，通过索引和正文检索候选，再检查正文、适用性和核对状态。每项答案要点对应有效知识点；检索匹配本身不等于足够依据。
- 默认模式列出教材定位、材料分析、对应知识点、参考答案和关键词；考试模式仅保留精炼采分点；讲题模式展示题眼到知识点的映射及来源。
- “标准答案”指教材支持的参考答案。没有用户提供的官方答案时，不声称答案是官方评分细则。
- 范围按完整流程推进：第二课先验收，其他课次逐单元扩展，最后验证全册索引、跨课问题和新副本使用。
- 规格、独立任务、讨论和验证记录均使用已配置的本地 Markdown 任务跟踪器。

## Testing Decisions

- 已与用户确认：按教材页面 → 核对文本 → 知识点 → 材料题答案的完整流程验收。自动检查尽量从本地脚本的公开命令入口观察输入输出；自然语言回答通过真实题目评估依据和适用性。
- 仓库目前没有脚本测试先例。新增必要测试围绕可观察行为：双页码保存、OCR 不自动核对、核对文本保留、未核对知识点排除、索引有效性、来源变化及缺少输入的明确失败。
- 重复运行测试必须检查实际修订保留，来源变化测试必须使用同名但内容不同的来源，避免只检查实现中的标志位或字段名称。
- 真实教材验收使用第二课完整 7 页，核对主要正文、标题、与知识点相关的栏目和页码；出现疑难时保留待核对状态，不为了通过验收擅自补字。
- 使用“小明觉得自己什么都不如别人”的现有材料题检验知识点检索及采分点来源。同题分别验证考试模式和讲题模式，比较依据一致性和表达是否适合初中生。
- 追加证据不足题、未核对内容和跨知识点问题，观察是否准确反映当前覆盖范围。
- 第一版三个技能进行结构校验，新增脚本实际运行。知识内容通过来源校验和题目验收验证，不添加只检查文档措辞或标题的测试。
- 单元扩展后校验知识点编号、题眼链接和来源完整性；全册完成后验证新副本中无需教材 PDF 即可使用已核对知识。

## Out of Scope

- 网站、数据库、服务端和自动调用外部大模型服务。
- OCR 自动输出未经核对的“教材原文”或未经依据支持的答案。
- 发布教材扫描件、页面图或全书逐字转录。
- 第一版的 Linux/macOS 自动 OCR 后端，以及其他年级、册次或版本教材。
- 自动评分、官方评分细则、错题管理系统和无限量题目生成。
